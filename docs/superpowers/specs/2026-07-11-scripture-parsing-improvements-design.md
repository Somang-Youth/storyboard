# 말씀 파싱 안정화 설계

## 목표

말씀 입력과 대한성서공회 본문 파싱에서 다음 세 가지 문제를 함께 해결한다.

1. `말씀: 로마서 10장 14~21절`처럼 풀네임과 한국어 `장`/`절`을 사용한 입력을 인식한다.
2. 로마서 9장 `1-2`처럼 여러 절이 하나의 원문 블록으로 제공되는 경우 단일 절 선택도 오류 없이 처리한다.
3. PPT와 말씀 미리보기에 숫자형 주석 표식과 한글 자모형 관주 표식 및 주석 본문이 포함되지 않게 한다.

## 입력 표기 정규화

`lib/scripture/notation.ts`에 순수 함수 `normalizeScriptureNotation`을 추가한다. 이 함수는 공백을 허용하면서 `장`을 `:`로 치환하고 마지막 `절`을 제거한 뒤 기존 파서가 이해하는 형식으로 반환한다.

- `로마서 10장 14절` → `로마서 10:14`
- `로마서 10장 14~21절` → `로마서 10:14~21`
- `로마서 10장 14-21절` → `로마서 10:14-21`

Discord 댓글 파서와 말씀 미리보기/PPT 파서가 이 함수를 공통으로 사용한다. 기존 축약형, 풀네임, 콜론 표기, 장을 넘는 콜론 범위는 현재 동작을 유지한다. `10장 14절~11장 2절`처럼 장을 넘는 한국어 표기는 이번 범위에 포함하지 않는다.

## 결합 절 블록

### 데이터 모델

`ScriptureVerse`를 단일 절 지점이 아닌 원문 블록의 포함 범위로 표현한다.

```ts
interface ScriptureVerse {
  book: ScriptureBook;
  chapter: number;
  verseStart: number;
  verseEnd: number;
  text: string;
}
```

일반 3절은 `[3, 3]`, 결합된 `1-2`절은 `[1, 2]`가 된다. 시작과 끝을 모두 필수 필드로 두어 이후 소비자가 결합 범위를 실수로 무시하지 않게 한다.

### HTML 파싱과 선택

절 번호는 단일 숫자와 하이픈 계열로 연결된 범위를 모두 인식한다. 범위의 시작과 끝이 양수이고 시작이 끝보다 크지 않은지 검증한다.

본문 요청 범위와 원문 블록 범위가 하나라도 겹치면 해당 블록 전체를 한 번 선택한다. 따라서 `롬 9:1`과 `롬 9:2`는 모두 `1-2` 블록을 반환하고 `롬 9:3`은 이 블록을 반환하지 않는다. 결합 본문은 분리, 복제, 잘라내기 하지 않는다.

누락 절 검증은 레코드 개수가 아니라 각 블록이 덮는 포함 범위를 기준으로 수행한다. 정렬된 블록의 범위 사이에 실제로 덮이지 않는 절이 있을 때만 기존 누락 오류를 반환한다.

### 표시와 페이지 분할

- 미리보기와 `{절번호}` 템플릿은 결합 블록을 `1-2`로 표시한다.
- 단일 결합 블록 페이지 제목은 `롬 9:1-2`로 표시한다.
- 내보내기 경계는 `verseStart: 9:1`, `verseEnd: 9:2`로 전달한다.
- 사용자가 요청한 상위 reference는 입력 의도를 보존해 `롬 9:1`로 유지하고, 실제 포함 본문 라벨만 `롬 9:1-2`로 표시한다.
- 결합 블록은 원자적으로 유지하되 슬라이드 용량과 최대 80절 제한에서는 포함된 절 수만큼 계산한다. 예를 들어 `1-2` 블록은 2절을 소비하며, 슬라이드 용량이 1이어도 분할하지 않고 단독 페이지에 둔다.

## 관주와 주석 제거

대한성서공회 HTML에서 숫자형 주석과 한글 자모형 관주는 모두 `a.comment` 요소로 표시되고, 주석 본문은 기존 `D_*`/`D1`~`D6` 요소에 들어간다. 문자열 정규식으로 자모를 삭제하지 않고, 각 절을 clone한 뒤 다음 요소를 `.text()` 호출 전에 구조적으로 제거한다.

1. `a.comment` 표식 요소
2. 기존 `[id^="D_"]`, `.D1`~`.D6` 주석 본문 요소

이 처리는 본문 공급자 경계에서 한 번 수행하므로 미리보기와 PPT가 모두 정제된 같은 텍스트를 받는다. 기존 숫자 표식 문자열 정리는 레거시 HTML을 위한 방어 로직으로 유지한다. `a.comment` 밖에 있는 일반 링크나 일반 한글 텍스트는 제거하지 않는다.

## 오류 처리

- 지원하지 않는 한국어 장절 형식은 억지로 변환하지 않고 기존 형식 오류 처리에 맡긴다.
- Discord 정규화는 기존처럼 파싱되지 않은 원문을 보존한다.
- 잘못된 결합 범위와 실제 누락 절은 명시적인 오류로 처리한다.
- 결합 블록이 요청 범위와 겹치면 일부 절만 요청했더라도 오류를 반환하지 않는다.

## 테스트 전략

모든 변경은 실패하는 회귀 테스트를 먼저 추가한 뒤 최소 구현으로 통과시킨다.

### 입력 표기

- 정확한 사용자 입력 `말씀: 로마서 10장 14~21절`이 `롬 10:14~21`로 추출되는지 검증한다.
- 단일 절, 하이픈 범위, 축약형, 기존 콜론 표기를 각각 검증한다.
- Discord 파서와 미리보기/PPT 참조 파서가 같은 결과를 내는지 검증한다.

### 결합 절

- 실제 형태의 `1-2`와 일반 `3` 블록을 HTML fixture로 파싱해 `[[1, 2], [3, 3]]`이 되는지 검증한다.
- `롬 9:1`과 `롬 9:2`가 각각 동일한 `1-2` 블록을 한 번만 선택하는지 검증한다.
- `롬 9:1~3`이 `1-2` 블록과 3절을 순서대로 선택하는지 검증한다.
- 실제 범위 공백은 계속 누락 오류를 내는지 검증한다.
- 미리보기 라벨, PPT 절 번호, 페이지 제목, 시작/끝 경계가 `1-2` 범위를 보존하는지 검증한다.
- `1-2` 블록이 슬라이드 용량과 80절 제한에서 2절로 계산되며 분할되지 않는지 검증한다.

### 관주와 주석

- `a.comment` 안의 `ㄱ)`과 연결된 `D_*` 관주 본문이 모두 제거되는지 검증한다.
- 한 절에 숫자형 `1)`과 자모형 `ㅂ)` 관주가 함께 있어도 모두 제거되는지 검증한다.
- 절 시작과 문장 중간에 관주가 있어도 표식만 제거되고 주변 단어와 공백이 정상인지 검증한다.
- 서로 다른 자모 표식이 여러 개 있어도 특정 자모 목록에 의존하지 않고 모두 제거되는지 검증한다.
- 관주가 전혀 없는 절은 기존 공백·절 번호 정규화 결과와 완전히 동일한지 검증한다.
- `a.comment`가 아닌 일반 링크와 일반 본문 텍스트는 유지되는지 검증한다.
- 기존 단순 숫자 표식 fixture도 계속 통과하는지 검증한다.

## 비목표

- 두 성경 권 매핑 또는 두 전체 파서를 하나로 통합하지 않는다.
- 대한성서공회 이외 공급자 형식을 추가하지 않는다.
- 결합 원문을 인위적으로 개별 절 문장으로 분리하지 않는다.
